# P9 能力核验与一级导航改造

日期：2026-07-27  
证据范围：当前 `skill-plugin-control-center` v0.2 的 `SKILL.md` 与只读命令、SkillDeck 本地源码、`http://localhost:4177` 的本地只读接口。  
结论状态：`verified` 表示已在当前源码或本地接口中核实；`partial` 表示只有部分链路；`missing` 表示当前没有该功能。

## 1. 原治理中心与 SkillDeck 对齐

| 能力 | 治理中心 | SkillDeck | 状态 |
| --- | --- | --- | --- |
| 实时盘点、来源、库存 | `inventory` | Skill 总览卡片、来源与相对位置 | verified |
| 搜索与单项检查 | `search` / `inspect` | 搜索、分类、状态筛选、详情 | verified |
| 五类整理状态 | `treatment` | 总览状态筛选与卡片标签 | verified |
| 健康与安全检查 | `audit` | 健康与安全一级页、摘要 | verified |
| 重复与差异 | `duplicates` / `compare` | 重复与合并一级页、差异比较 | verified |
| 吸收、合并、优化、隔离 | `plan` | 单项治理操作卡、重复组合并卡、旧入口隔离卡 | verified，但均未执行 |
| 创建 Skill、路由 Skill、插件 | `create-*-plan` | 创建与路由一级页 | verified，但只生成官方委托卡 |
| 组件与旧入口收敛 | `components` / `legacy-management` | 迁移与隔离一级页 | verified |
| 别名、场景、同步 | 只报告证据状态，不假定配置存在 | 没有独立页面 | partial |

治理中心仍是唯一库存事实来源。SkillDeck 不自行扫描任意目录，也不维护第二套库存。

## 2. 多个现有 Skill 合并成插件

| 层级 | 当前能力 | 状态 |
| --- | --- | --- |
| 合并两个重复 Skill | 可比较差异并生成 `merge` 操作卡 | verified，未执行 |
| 创建 Skills-only 插件 | 可生成 `create-plugin-plan` 官方委托卡 | verified，未创建 |
| 创建调用多个 Skill 的路由 Skill | 可生成路由 Skill 的创建委托卡 | verified，未创建 |
| 把多个现有 Skill 复制/迁移进一个新插件 | 没有选择成员、依赖检查、复制、验证、回滚的执行链路 | missing |

因此，当前产品可以“规划合并”和“规划创建插件”，但不能声称已经实现“把多个现有 Skill 打包成插件”。这项能力若开发，必须先做成员选择、冲突与依赖预检、备份、逐个复制验证、回滚 manifest，并要求针对计划 ID 的单独确认。

## 4. 一级直达导航

左栏改为以下平级入口：

1. Skill 总览
2. 健康与安全
3. 重复与合并
4. 创建与路由
5. 迁移与隔离
6. 专家组合
7. 模型与隐私

点击“健康与安全、重复与合并、创建与路由、迁移与隔离”时，主区仅展示该功能的对应页面，而不是先进入综合治理页再寻找功能。优化、吸收、单项隔离仍在 Skill 详情中，因为它们必须先明确选中一个具体 Skill。

## 安全边界

- 本轮不加入一键删除、自动合并、自动创建或未确认的外部调用。
- 所有治理按钮继续只生成 `not_executed` 操作卡。
- `.system` Skill 与插件缓存继续只能登记、观察，不能在控制台处理。
