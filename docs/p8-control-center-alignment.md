# P8｜技能管理中心与 SkillDeck 控制台功能对齐

状态：已确认的开发范围（2026-07-27）  
前台：SkillDeck  
唯一治理事实来源：`skill-plugin-control-center`

## 结论

原技能管理中心已经拥有盘点、检查、比较、吸收、合并、进化、隔离、创建及路由设计能力；其中会改变技能库的动作目前都只有**操作卡**，不是已经可直接执行的命令。

P8 的目标是把这些治理能力完整呈现在 SkillDeck 中，保持同一份实时库存和同一套确认门。P8 不实施永久删除、自动合并、自动创建或自动同步。

## 对齐范围

| 原治理能力 | P8 前台呈现 | P8 输出 | 是否改动技能库 |
| --- | --- | --- | --- |
| 盘点、来源、五类状态 | 卡片墙与治理摘要 | 当前实时库存 | 否 |
| 健康与安全检查 | 治理工作台的健康报告 | 静态问题与风险线索 | 否 |
| 同名/同 SHA 重复检查 | 重复组列表与两项差异比较 | 候选主版本、差异、下一步 | 否 |
| 吸收 | 单项治理操作 | 吸收操作卡 | 否 |
| 合并 | 重复组双项选择 | 合并操作卡 | 否 |
| 优化/进化 | 单项治理操作 | 进化操作卡 | 否 |
| 删除 | 改名为“可回滚隔离” | 隔离操作卡及回滚说明 | 否 |
| 创建普通 Skill | 创建向导 | 官方 `skill-creator` 委托卡 | 否 |
| 创建插件 | 创建向导 | 官方 `plugin-creator` 委托卡 | 否 |
| 创建调用其他技能的 Skill | 路由 Skill 创建向导 | 普通 Skill 创建卡 + 路由设计说明 | 否 |
| 旧管理 Skill 收敛 | 迁移清单 | 吸收/观察/隔离候选说明 | 否 |

## P8 用户流程

1. 在左侧进入“治理工作台”。
2. 选择健康、重复、创建或旧能力迁移。
3. 在重复组中选定两份副本，可生成“比较”或“合并”操作卡。
4. 在任一 Skill 详情中，可生成“优化”“吸收”或“可回滚隔离”操作卡。
5. 创建向导只做名称冲突和目标路径预检，输出官方创建器的委托卡。
6. P9 才能在用户确认**某一张计划 ID**后，进入备份、最小范围执行、验证和回滚流程。

## 安全边界

- SkillDeck 不重新扫描或维护第二份库存；所有数据由技能管理中心实时读取。
- 所有 P8 接口只允许固定治理命令和已存在的稳定 ID；不提供任意目录、任意脚本或任意文件入口。
- 不展示绝对路径、不读取完整 Skill 正文、不连接外部 API。
- “删除”永远先显示为“可回滚隔离”；永久删除不在 P8 或 P9 默认范围内。
- 插件缓存和 `.system` Skill 仅登记/观察，不允许隔离或合并。

## 验收标准

- 同一 Skill 在卡片、详情和治理操作中保持相同的名称、稳定 ID、来源和治理状态。
- 所有操作只返回 `not_executed` 操作卡，且响应明确显示 `local_execution_started: false`。
- 合并必须恰好选择两个当前库存中的 Skill；比较不读取正文以外的未授权内容。
- 创建卡会阻止非法名称和同名冲突，且只指向官方创建器。
- 治理中心不可用时，SkillDeck 不退回到旧的任意目录扫描。

## P9 前置条件

只有用户确认一张具体计划卡，且该卡包含目标、差异、依赖线索、备份、验证与回滚时，才可设计单项执行器。执行器必须先支持回滚，再考虑可回滚隔离或单项合并。
