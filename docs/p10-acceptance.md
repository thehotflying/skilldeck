# P10 验收说明：通用场景与插件治理工作台

日期：2026-07-27  
范围：SkillDeck 本地前台与现有 `skill-plugin-control-center` 治理内核。  
本轮没有启动真实迁移、合并、隔离、创建、安装、卸载、发布或外部模型调用。

## 已实现

### 1. 通用场景工作台

已提供三种固定的通用场景：

- PPT 工作台；
- 文档写作工作台；
- 信息收集工作台。

每个场景从治理统一库存按固定分类和关键词规则筛选候选 Skill，展示建议职责顺序、成员的治理状态和风险线索。用户可显式勾选 1–12 个 Skill，生成本场景任务方案卡。

这不是自然语言自动触发：页面不会因为一句模糊描述而自行执行、调用或外发任何 Skill。

### 2. 插件装配

已可从当前统一库存选择 2–12 个 Skill，生成：

- 建议职责划分；
- 同名/重复关系线索；
- 脚本、联网、写入、账号等静态风险线索；
- “依赖未知，需人工复核”的明确标记；
- 插件名称、入口、建议子 Skill、测试、备份、回滚和具体计划 ID。

当前只生成 `not_executed` 计划卡。不会复制 Skill、创建插件目录、写入 manifest、移动旧文件或删除副本。

### 3. 我的插件

已通过技能管理中心固定的只读 `inventory` 命令读取当前可发现的已安装插件，显示：

- 插件名称、市场来源、版本与安装状态；
- 仅在个人插件缓存中已观察到时显示组成 Skill；
- 未观察到组成时明确显示“未知”，不会推断为空；
- 新增、替换、合并、拆分、优化、回滚的变更计划卡。

变更卡均保留备份、验证、回滚和具体确认门；不直接修改插件。

### 4. 安全边界

- 唯一 Skill 事实来源仍是 `skill-plugin-control-center`；
- 不接受任意目录或绝对路径作为接口输入；
- 前台 API 输出不显示绝对路径；
- 旧版任意扫描/直接执行入口继续返回 `410`；
- 模型未配置时，连通性测试返回“未配置”且 `external_request_started=false`；
- 任何真实 API 调用、真实迁移、真实合并、隔离、创建或安装都需要具体计划 ID 和单独确认。

## 需要用户选择

1. 场景工作台中具体采用哪些候选 Skill；
2. 插件装配的名称、用途、成员与入口；
3. 已安装插件要生成哪一种变更计划；
4. 若要实施真实变更，需要确认哪一张具体计划卡。

## 需要用户配置

若需真实 AI 推荐或模型连通性测试，用户需要在“模型与隐私”页提供 API 地址、模型名和密钥。密钥只应进入 macOS 钥匙串；本轮没有猜测、写入或使用任何 API 配置。

## 未验证或未实现

- 多个现有 Skill 的真实迁移/打包为一个插件；
- 真实合并、隔离、创建、安装、卸载或回滚；
- 对任一真实模型服务的连通性和推荐质量；
- Codex 新任务中对本次更新后 UI/插件的人工端到端体验。

## 验证结果

本地安全验证覆盖：

- 三个场景均可返回候选；
- 场景方案、插件装配计划、插件变更计划均为 `not_executed`；
- 已读取当前 28 个已安装插件；
- 测试输出未出现绝对路径；
- 未配置模型时，外部请求没有启动；
- 旧直接执行端点维持 `410`；
- 原有治理、调用门和模型配置测试继续通过。
